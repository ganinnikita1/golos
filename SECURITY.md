# Безопасность «Голоса»

## Известные уязвимости и версии

| Версия | Статус | Примечание |
|---|---|---|
| 0.1.0 | **не публиковалась** | Critical: модель скачивалась с изменяемой ветки HF и исполнялась без проверки целостности (возможен RCE при компрометации HF-репозитория). Заменена на 0.1.1. |
| 0.1.1+ | актуально | Ревизия модели закреплена по commit SHA, SHA256 файлов сверяется до исполнения remote-кода. |

Если у вас есть сборка 0.1.0 — обновитесь до 0.1.1 и удалите каталог модели, чтобы
перекачать её по закреплённому коммиту (приложение проверит хеши автоматически).

## Проверка скачанных файлов

Релизы сопровождаются файлом `SHA256SUMS`. Проверка (PowerShell):

```powershell
Get-FileHash .\golos-0.1.1-source.zip -Algorithm SHA256
# сравните с содержимым SHA256SUMS в релизе
```

Сборка exe: используйте исходники из тега и `packaging/build.ps1`; не берите
готовые exe из неофициальных источников.

## Модель угроз кратко

Активы: записи микрофона, распознанный текст, API-ключи (если включены
облачный ASR/LLM), GitHub-аккаунт владельца, целостность приложения у пользователя.

Границы доверия:

1. **Локальная машина пользователя.** Аудио и история обрабатываются локально.
   Приложение не отправляет их в сеть, если пользователь сам не включил облачные
   функции (по умолчанию выключены).
2. **Hugging Face (загрузка модели).** Модель — это не только веса, но и код
   (`modeling_gigaam.py`), который исполняется локально. Подмена модели на HF —
   главный внешний вектор атаки. Мы фиксируем ревизию на неизменяемом commit SHA и
   сверяем SHA256 всех файлов с манифестом `golos/asr/model_manifest.json`
   **до** импорта remote-кода; при несовпадении загрузка прерывается.
   Хеши сгенерированы из официальных метаданных HF (для LFS-файлов — SHA256 от HF)
   и кросс-проверены (`tools/gen_model_manifest.py`).
3. **PyPI / зависимости / GitHub Actions.** Зависимости ставятся из PyPI; действия
   CI закреплены по SHA, права `GITHUB_TOKEN` минимальны (read-only), Dependabot
   отслеживает обновления. Для пользователей, собирающих exe сами, рекомендуется
   собирать из тега и сверять исходники.
4. **Локальные данные.** Конфиг, история и логи лежат в профиле пользователя
   (`%APPDATA%\Golos`); права — обычные для профиля Windows. Распознанный текст
   намеренно **не** пишется в лог; в логах — длительности, RTF и служебные события.

## Модель приватности

* **Распознавание речи выполняется локально** на CPU. Аудио не покидает компьютер.
  Модель один раз скачивается с Hugging Face и работает офлайн.
* **Вставка текста по умолчанию не использует буфер обмена**: текст вводится напрямую
  через `SendInput`. В режиме буфера содержимое восстанавливается, а диктовка
  исключается из журнала Windows (Win+V) и облачной синхронизации.
* **LLM-полировка выключена по умолчанию.** Если включить, на указанный вами сервер
  отправляется только текст распознанной фразы (не аудио).
* **Облачный ASR выключен по умолчанию.** Если включить, аудио отправляется на
  выбранный endpoint по HTTPS, ключ берётся из переменной окружения.
* Секреты (API-ключи) не хранятся в коде и не пишутся в логи: приложение читает их
  из переменных окружения, имена которых задаются в настройках.
* Пути в интерфейсе и диагностике показываются как `%APPDATA%`/`%LOCALAPPDATA%`/
  `%USERPROFILE%` — имя учётной записи не попадает на скриншоты и в публикуемые
  отчёты. «Скопировать сведения» в настройках тоже отдаёт обезличенный текст.

## Что не следует публиковать

* API-ключи и токены (`OPENAI_API_KEY`, `DEEPSEEK_API_KEY`, `HF_TOKEN` и т.п.).
* Персональные записи речи и фрагменты переписки.
* Логи и дампы с персональными данными: `%APPDATA%\Golos\logs`, история распознаваний.
* Скриншоты с реальными путями/именами — используйте диагностику из приложения,
  она обезличена.

## Как сообщить об уязвимости

Не создавайте публичный issue для проблем безопасности. Используйте
**GitHub Security Advisories** («Security» → «Report a vulnerability») в репозитории.
Опишите: версию, шаги воспроизведения, потенциальное влияние. Мы постараемся
ответить в разумный срок и подготовить исправление до публичного раскрытия.

## Известные ограничения, не являющиеся уязвимостями

* Windows не позволяет непривилегированному процессу вставлять текст в окна,
  запущенные с повышенными правами (UIPI) — для таких приложений запускайте «Голос»
  от администратора.
* Глобальный хук клавиатуры по определению видит нажатия клавиш — это необходимо для
  работы горячей клавиши; нажатия не записываются и не передаются.
* Если пользователь вручную разрешит `asr.allow_unverified_model` или укажет свой
  репозиторий модели, проверка хешей для неё не применяется — это осознанное
  изменение границы доверия.
* Скомпрометированная локальная учётная запись Windows может читать файлы приложения
  (как и любые файлы пользователя); защита от этого — вне области приложения.
