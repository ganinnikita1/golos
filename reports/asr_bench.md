## Рекомендация

Для диктовки рекомендуется **GigaAM-v3 / e2e_rnnt**: WER 4.4% (без учёта нормализации чисел — 1.6%), CER 3.1%, RTF 0.069, пунктуация в конце фразы — 97% случаев, заглавная в начале — 97%. e2e-модель сразу отдаёт нормализованный текст с пунктуацией, поэтому отдельный пунктуатор приложению не нужен. Сырой вариант GigaAM-v3 / rnnt даёт WER без чисел 0.5%, но не ставит знаки и заглавные (пунктуация 0%), поэтому без отдельного пунктуатора для диктовки не подходит. Для сравнения, faster-whisper large-v3-turbo: WER без чисел 1.3% (сопоставимо), но RTF ~1.10 — примерно в 14 раз медленнее GigaAM, и пунктуация в конце только 42%. На CPU-only машине для диктовки он проигрывает.

## Ограничения и нюансы

- **Числа.** e2e-ревизии по контракту нормализуют речь: «сто двадцать пять рублей» → «125 ₽», «четыреста четыре» → «404». Обычный пословный WER штрафует их за это, поэтому в таблице есть колонка «WER без чисел» (цифры и числительные → `<num>`), а сырые ctc/rnnt наоборот пишут числа словами и на таких фразах выглядят лучше. Для диктовки цифровая запись — это норма и плюс, а не ошибка.
- **Пунктуация.** Сырые ctc/rnnt не ставят знаки и заглавные (0% в таблице) — их пришлось бы прогонять через отдельный пунктуатор. e2e-ревизии отдают готовый текст.
- **Загрузка.** Время «Загрузка» для e2e_ctc/ctc/rnnt из таблицы включает первичное скачивание ревизии (~420 МБ, ~15 c) — эти ревизии не были в кэше; у faster-whisper в него входит скачивание ~1.6 ГБ (60 c). Чистая загрузка GigaAM в память ~5–8 c на первой ревизии (импорт remote-кода ~4 c) и ~1–2 c на последующих.
- **faster-whisper.** large-v3-turbo int8 на CPU даёт сопоставимый WER (4.1%, без чисел 1.3%), но RTF ~0.9–1.1 — в 13–16 раз медленнее GigaAM, и конечную пунктуацию ставит лишь в 42% фраз. Для CPU-диктовки проигрывает по обоим ключевым для продукта параметрам (скорость и готовый текст).
- **Шум измерений.** Бенчмарк шёл параллельно с другими задачами на той же машине, поэтому отдельные RTF-выбросы (например 0.45 на одной короткой фразе) — это конкуренция за CPU, а не свойство модели. Ориентируйтесь на медиану и на замер RTF на длинной фразе (10–15 c), он стабильнее.
- **Синтез.** Датасет — TTS (SAPI Irina), поэтому это верхняя оценка качества: на реальном микрофоне/шуме WER будет выше. Реальные записи можно добавить через `--real-manifest` (JSON со списком `{wav, text}`).
- **Реальная запись.** Кроме TTS в набор добавлена настоящая запись (33.4 c, публичный HF-датасет Speech-data/russian-speech-dataset, CC BY-NC-ND). e2e_rnnt распознал её с WER 0.0% — заодно проверена нарезка длинного аудио на чанки и склейка без дублей на живой речи.

## Методика

WER/CER считаются по нормализованному тексту (нижний регистр, пунктуация убрана, ё→е) — стандартная практика, чтобы не штрафовать модель за знаки. Пунктуация и заглавные оцениваются отдельно по сырому выводу модели. RTF = время распознавания / длительность аудио; цель приложения — RTF < 0.35 на 10–15-секундной фразе. Длинное аудио (> 20 c) движок режет на чанки с перекрытием 0.5 c и склеивает текст без дублей.
